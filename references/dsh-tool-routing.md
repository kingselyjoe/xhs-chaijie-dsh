# DSH 工具路由与能力恢复

仅在网页读取、站内搜索、图像理解、OCR、文件写入、HTML 预览或安装能力需要判断时读取。

## 运行前检查

先观察当前 DSH 会话已经暴露的工具与 Skill，不把工具名写死。按能力而不是品牌选择：

| 任务 | 首选 | 次选 | 最低可行材料 |
|---|---|---|---|
| 读取账号主页 | 用户已登录且授权的浏览器标签页 | 公开网页读取/平台连接器 | 主页完整截图与主页链接 |
| 站内找对标 | 小红书站内搜索 | 社交连接器 | 外部搜索候选，逐项待验证 |
| 读取笔记 | 笔记详情页 | 用户导出的文本与截图 | 标题、日期、正文、互动和详情链接 |
| 封面审计 | 原图或完整截图 + 视觉能力 | OCR + 人工可见截图 | 3-5 张完整封面 |
| 生成报告 | DSH 文件写入能力 | 可授权的项目工作区 | 完整 Markdown 降级交付 |
| 验证报告 | 浏览器本地预览 + 脚本 | 文件打开/截图 | 结构与链接脚本检查 |

## 访问状态

开始采集或搜索前明确写出一种状态：

- `站内可访问`：已实际打开小红书主页、搜索页或笔记，并获得可点击的小红书 URL。
- `仅外部网页搜索`：候选只能写“外部搜索待验证”，不能据此发布正式热度排名。
- `仅用户材料`：分析范围严格限定在用户提供的截图、导出和链接。

## 能力恢复顺序

第一次失败不代表最终不可用，按下列顺序恢复：

1. 写明失败步骤和缺少的具体能力，例如“需要读取已登录的小红书标签页”。
2. 检查当前已安装 Skills、插件、MCP/连接器、浏览器控制、Computer Use、网页、OCR、视觉和文件工具。
3. 向宿主提出一个具体问题，不一次堆砌工具名。
4. 优先使用现有能力、已打开标签页或官方插件/市场入口。
5. 任何安装、登录、Cookie、浏览器或文件权限先说明动作与风险并取得同意。
6. 内置路径都失败后，再提供外部工具、用户截图/导出或省略模块的方案。

可用问法：

> 当前需要读取你已登录的小红书主页和笔记完成公开数据采集。这个 DSH 环境是否提供浏览器控制、现有连接器或已打开标签页访问能力？

## 安全边界

- 不要求用户把密码或完整 Cookie 粘贴到聊天、仓库或报告。
- 不绕过验证码、登录、权限、频控或反自动化机制。
- 不自动安装第三方组件；安装前说明来源、权限与风险并等待许可。
- 不调用未公开接口或伪装真人操作规避平台限制。
- 用户撤回授权时停止访问对应浏览器、文件或账号。

## 低能力环境降级

如果 DSH 环境只有基础代码与文件能力：

1. 请求主页完整截图，包含头像、账号名、简介、公开互动与置顶。
2. 请求最近 20-30 篇笔记列表截图，能辨认标题、封面、日期和互动。
3. 请求 TOP 5 详情，包含标题、日期、公开互动、正文和评论。
4. 请求 3-5 张代表封面原图或完整截图。
5. 材料不全也可开始，但在数据说明中逐项标注缺失，并缩小结论范围。

外部工具只能作为用户主动选择的增强项，不能成为 Skill 的强制依赖。
